# Quilvori · 叙翎集

キャラクターを書き、世界を組み立て、散らばった設定を使いやすく整えるローカルの作業机です。✍️

[English](README.md) · [中文](README.zh.md) · **日本語** · [Русский](README.ru.md) · [한국어](README.ko.md) · [ไทย](README.th.md)

Quilvori は SillyTavern 用の素材を作るためのアプリです。キャラクターカードやワールドブックを編集し、自分で設定したモデルと相談して推敲し、SillyTavern に読み込めるファイルへ書き出せます。手動編集、インポート、ローカル検査、バックアップは単独で使えます。AI 機能には別途モデルサービスが必要です。

## コレクション、画面の配色、素材カタログ

表紙のタイトル横にあるピンで、キャラクターカードやワールドブックを本棚の先頭に固定できます。解除すると元の並び順に戻ります。固定状況はライブラリのバックアップに保存され、SillyTavern への書き出しには含まれません。

ホームはキャラクターの肖像とワールドブックの表紙を大きく並べるコレクションです。検索、種類別の絞り込み、原文プレビュー、新しいカード／本の作成を利用できます。肖像がない作品には文字の表紙を表示し、代わりの作品画像は生成しません。蔵書票風の飾り罫、表紙の角飾り、蔵書印を添えています。

画面ごとに落ち着いた配色を使います。コレクションは薄紫、AI は青紫、カードはローズグレー、本はセージ、執筆ツールはシャンパン、構造ツールはスレートブルー、閲覧は暖かい茶色、物語はプラム、素材とリソースはスモーキーピンク、管理はグラファイトです。設定の外観と言語で画面別配色とカスタム色を切り替えられ、保存済みのカスタム設定は保持されます。

新規プロフィールの初期言語は英語です。更新しても保存済みの対応言語は維持されます。中国語・英語・日本語・ロシア語・韓国語・タイ語に対応し、言語切替で作品本文や作者名は翻訳しません。

素材カタログでは作者の原画像プレビュー、署名、紹介、元投稿、利用条件を確認できます。カード、本、壁紙を扱いますが、個人ライブラリのミラーや任意の Discord 投稿を自動検索する機能ではありません。元投稿には自分のアカウントやサーバー参加権限が必要な場合があります。気に入った作品は元投稿のコメントで作者を応援してください。アプリが代わりに投稿することはありません。

再配布許可が確認できない項目には作品ファイルを同梱しません。元投稿から添付ファイルのリンクをコピーしてインポートします。カード PNG/JSON とワールドブック JSON はプレビュー後に保存し、ダウンロード上限は 12 MB です。Web 版には CORS 制限があり、Discord のリンクが期限切れなら再取得してください。壁紙は PNG/JPEG/WebP のみ、入力は 12 MB・一辺 8192 ピクセル・4000 万画素までです。ローカル保存用コピーは長辺 1600 ピクセル・500 KB 以下に縮小されます。元の高解像度画像は作者から入手してください。SVG、Web ページ、テーマファイルは壁紙として読み込みません。

作者と元投稿の情報は安全な形式で保持され、編集画面の折りたたみ欄とカード／本の `quilvori_source` 拡張に残ります。公開されていることは再配布の許可を意味せず、作品にこのリポジトリの GPLv3 ライセンスが自動適用されることもありません。貢献前に英語の [CONTRIBUTING.md](CONTRIBUTING.md) をお読みください。

## できること

- 外見・背景、性格、シナリオ、挨拶、会話例、ロールプレイ指示を編集し、プレビューで確認。
- 一つの欄に混在した設定を、原文と移動先の既存内容を保ったまま適切な欄へ整理。
- 無題のワールドブック項目に名前、分類、主キーワードを補い、本文は保持。
- 選択した欄、項目、文章だけを AI に修正してもらい、比較してから反映・取り消し。
- 採用したアイデアと現在の下書きを使って相談し、続きを修正。
- 人物設定、事実、時系列を検査し、引用と読みやすい原文の場所を確認。
- プロンプト、正規表現、クイック返信、関係図、時系列、HTML 記憶を管理。

### 酒場のテーマ工房

テーマ工房では JSON を選ぶか、Discord の元投稿または添付リンクを貼り付けます。Selenis の Lavender Blossoms、Dascard の Inkflow Radiance（PC）、GrizzyBurr の Solarized Light に作者名と元投稿を記載しています。端末にファイルがなければ元投稿から入手できます。色・透明度・ぼかしを調整し、壁紙を選んでプレビューしてから、作者の CSS と出典を含む ST 用 JSON を書き出せます。

デスクトップ版で SillyTavern のインストール先、data またはユーザーディレクトリに接続すると、既存テーマの読み込みと切り替え、編集したコピーの適用ができます。複数のユーザーがいる場合は対象を選び、開いている酒場のページを再読み込みしてください。作者のカスタム CSS は明示的に選択できます。壁紙と Info Board は別の素材です。

## クイックスタート

リポジトリをダウンロードするか、Git で取得します。

```bash
git clone https://github.com/ShangguanQian/Quilvori.git
cd Quilvori
```

### ウェブ版

Python 3 と新しいブラウザーが必要です。ウェブ版に npm 依存関係のインストールやビルドは不要です。

```bash
python3 -m http.server 8765 --bind 127.0.0.1
```

Windows では次も使えます。

```powershell
py -m http.server 8765 --bind 127.0.0.1
```

[http://127.0.0.1:8765/](http://127.0.0.1:8765/) を開き、使用中はサーバーを動かしておきます。別のポートも使えますが、ポートが異なるとブラウザーのライブラリも別になります。

`index.html` を直接開く方法もあります。ファイルページでの保存や API 通信が制限される場合はローカル HTTP サーバーを使ってください。保存できない状態で閉じる前には、ライブラリ全体をバックアップします。

### デスクトップ版

0.2 以降の Windows x64 版は、ダブルクリックで起動できる単一の `.exe` です。Mac では Apple シリコン用の `arm64` または Intel 用の `x64` の `.dmg` を開き、**Quilvori** を「アプリケーション」にドラッグして起動します。どちらにも Electron が含まれます。 [リリースをダウンロード](https://github.com/ShangguanQian/Quilvori/releases)

#### ソースから起動する

Node.js 22.12 以降と npm を用意し、リポジトリ直下で次のコマンドを実行します。

```bash
npm ci
npm start
```

Windows では依存関係を導入した後、リポジトリの [Start-Quilvori.cmd](Start-Quilvori.cmd) をダブルクリックすることもできます。スクリプト自身の場所からプロジェクトを探すため、別の作業ディレクトリからも起動できます。プロセスの起動成功後はコンソールを閉じ、失敗時はエラーを表示したまま待機します。Node.js 22.12 以降が必要です。依存関係がなければプロジェクトで `npm ci` を実行するよう案内し、自動ダウンロードやグローバル Electron の代用はしません。

デスクトップ版では、選択したローカルフォルダーからカードやワールドブックを読めます。

## 初めて使うとき

1. 新しいライブラリには「听雨楼」のサンプルが入ります。編集、検査、書き出しを試せます。「未名客」は空欄を残した下書きです。
2. サイドバーからカードの JSON／PNG、ワールドブックの JSON を取り込みます。対応ページへのドラッグ＆ドロップも使えます。
3. カードの「項目を整理」やワールドブックの AI 整理で、既存の資料を整えます。
4. 書き換える場合は「AI 創作」の既存編集で範囲を選び、要求を入力します。
5. プレビューを確認して必要な提案を反映し、SillyTavern 用に書き出します。全体バックアップも保存してください。

サンプルの読み込みとライブラリ消去には確認があります。サンプルを再読み込みすると現在のライブラリを置き換えるため、自分の資料は先にバックアップしてください。

## AI モデルの接続

設定のモデル接続画面で次を行います。

1. `https://api.openai.com/v1` など、利用先の API ベース URL を指定します。個々のリクエストの完全な URL は入れません。
2. 自分の API キーとプロトコルを設定し、接続します。
3. サービスが返した一覧からモデルを選び、短いテストメッセージで接続を確認します。
4. 必要に応じて推論強度を選びます。既定値では追加パラメーターを送信しません。対応段階はモデルとサービス次第です。

OpenAI 互換の **Responses** と **Chat Completions** に対応しています。自動では Responses を優先し、エンドポイントが未対応の場合に切り替えます。Chat Completions のみのサービスでは、その方式を直接選べます。認証失敗や不正な応答はエラーとして表示します。

推論強度が高いほど通常は時間がかかります。未対応の強度なら既定値か対応段階へ戻してください。利用可否、生成品質、料金は利用するモデルサービスによります。

モデルプロファイルごとに無通信時のタイムアウトを 1～60 分で設定できます。初期値は 5 分で、データを受け取るたびに計り直します。タスク履歴には最初のデータを待っていたか、受信の途中で途切れたかが表示されます。

手動作業はオフラインでも行えます。AI の生成・整理・相談・検査を実行すると、選んだ原文、参考資料、要求、関連する会話を設定先の API に送ります。デスクトップ版は Windows のユーザー保護または macOS のキーチェーンでモデルキーを暗号化します。Web 版は IndexedDB に保存したエクスポート不能な Web Crypto 鍵を使用します。移行時は各キーを復号できることを確認してから旧設定を置き換えます。モデルキーはカードやライブラリのバックアップには含まれません。

## AI の使い分け

### 既存の資料を修正

カードかワールドブックを選び、編集してよい欄や項目を指定します。原文内の選択範囲だけを修正することもできます。他の資料は参考として使い、修正前後を比較してから反映します。

返されなかった欄は元の値を保持します。既存内容の消去には明示的な許可が必要です。確認質問、不完全な応答、範囲外の変更、待機中の原稿変更は自動で上書きしません。取り消しも、その後の手動編集を上書きしないよう検査します。

### 新規作成と下書きの継続

目的を書いて生成を開始してください。質問への回答とアイデアの採用は任意です。記入した回答と選んだアイデアが生成に使われます。

相談には現在の下書きと採用したアイデアを使います。生成・相談・整理・検査の途中でも、同じウィンドウで別のページを開けます。元の作品に戻ると進み具合や結果を確認できます。カードやワールドブックは、選んだ欄や項目だけを再編集することもできます。

新規のキャラクターカードとワールドブックは端末に下書きとして保存されます。コレクションまたは各編集ページの「追加待ちの AI 下書き」から確認・採用し、「追加した作品を開く」でその作品へ移動できます。グループや台本、関係図が新しい人物を参照する場合は、まずそのカードを採用してください。

カードとワールドブックが同じ応答に含まれる場合、選択した作品ごとに検証します。一方に問題があっても、有効な作品は下書きに残ります。標準では、カードとワールドブックに関する直近24件のリクエスト記録をこの端末に保存します。本文がない場合は終了状態を記録します。「生成した作品」から下書きや収録済みの作品を個別に開けます。創作画面のタスク記録から復元するか、旧版でコピーした応答を貼り付けてください。復元は端末内で完結します。相談では通常の文章で返事を受け取り、その内容から下書きを修正できます。

### 論理と人物設定の検査

ローカルルールと AI 検査は分けて表示します。報告には平易な結論、理由、対応案があり、引用の場所をカードの欄、または「ワールドブック → 項目 → 欄 → 行」で示します。

原文を開いて確認し、報告へ戻れます。報告は生成時の引用位置を保持し、原稿が変わると再検査を促します。任意の空欄は参考情報として表示します。矛盾の判定には、原文で特定できる別々の箇所が少なくとも2つ必要です。引用が1つだけの場合や範囲が重なる場合は、報告と書き出した JSON の両方で要確認になります。検査そのものは原稿を書き換えません。

大きなワールドブックは項目を選んで分割検査でき、対象範囲を明記します。タスク記録では進行状態、サービスが返した推論、結果を区別し、推論が返らなかった場合も明示します。

## カードの項目整理

カード編集画面で整理を開き、任意の分類方針を添えてプレビューを作ります。

- 説明、性格、シナリオ、最初の挨拶、会話例、システム指示、履歴後指示、作者メモを対象にします。
- 各提案で移動元、移動先、理由、欄ごとの前後を確認できます。
- 原文をそのまま移し、移動先に既にある文章へ追記します。未選択の部分や判断できない部分は元の場所に残します。
- 移動元からの除去と移動先への追加は同時に反映します。引用不一致、重複範囲、原稿の変更があると反映しません。

既存資料の整理なので、足りない経歴を創作しません。分類結果は確認し、任意欄は必要がなければ空白のままで使えます。

## ワールドブックの整理

現在の項目、無題またはトリガー語が不足する項目、現在の本の全項目を選べます。項目編集側から一項目だけを開くこともできます。

- 人物、関係、場所、組織、ルール、歴史、品物、物語、その他に分類し、一覧を内容別に切り替えられます。
- 既定では無題・新規項目の名前だけを補います。既存名の変更は別途許可します。
- 主キーワードは本文または元の項目名から選び、既存の主・副キーワードを保って追加します。
- 常時有効の項目にキーワードは必須ではありません。常時有効の方式変更は、専用の許可を選んだ場合のみ提案します。
- キーワード方式へ変えるには主キーワードが最低一つ必要です。本文、有効状態、選択条件、挿入位置、深さ、順序は整理でリセットしません。

根拠と理由を確認し、選択した項目を反映・取り消しできます。分類は書き出し時に `realmweave_category` 拡張へ保存され、SillyTavern の発火設定とは別の情報です。

## SillyTavern への入出力

プロンプトプリセットに複数の実行順序がある場合は、編集する `character_id` を選びます。書き出しには選択した範囲の識別子、順序、有効・無効の設定が引き継がれます。その範囲に含まれないブロックも編集画面に残り、有効にすると実行順序に加わります。

| 資料 | 形式と読み込み先 |
| --- | --- |
| カード | `chara`／`ccv3` データ入り PNG または JSON。酒館の人物インポートを利用し、書き出し時には本も添付可能。 |
| ワールドブック | World Info JSON／キャラクターブックの `entries` 配列。世界情報から読み込み。 |
| 正規表現 | JSON 配列を Regex 拡張から読み込み。 |
| クイック返信 | Quick Reply v2 JSON を対応拡張から読み込み。 |
| 表情 | 対象人物の `expressions` フォルダー。本が記録するのはパック名だけです。 |
| プロンプト | 酒館プリセットと比較するブロック設定。モデル・温度を含む API プリセット全体の代わりではありません。 |
| グループチャット | 人物を読み込んでから群を作るための名簿。共通の群インポート形式ではありません。 |
| チャット閲覧・物語ノート・台本 | 工房の閲覧・構成用ファイルです。モデルに指示を挿入する作者ノートは SillyTavern の該当チャットで設定できます。 |
| HTML 記憶 | 酒館助手／JS-Slash-Runner で HTML スクリプトとして読み込み。 |
| 全体バックアップ | Quilvori 用 JSON。SillyTavern サーバー全体のバックアップではありません。 |

### ローカルフォルダーを読む

デスクトップ版でローカルフォルダー欄を開き、人物・世界書のフォルダーを選んで既存ファイルを読み込みます。対象は選んだフォルダー直下のカード JSON／PNG と世界書 JSON です。カード内の本も取り込みます。

PNG カードの肖像だけが変わった場合も別版として追加し、手元の編集を保持します。同じ版を再び読み込むと既存のカードが使われます。一つのファイルが失敗しても残りを続行し、詳細に失敗理由を表示します。大きな肖像は縮小します。容量不足なら本文を先に保存し、空き容量を増やして再スキャンすると肖像も取り込めます。読み込みは元カード・世界書を変更しません。デスクトップ版で表情画像を書き出す際は、置換対象のファイル名を確認してから実行します。途中で失敗した場合は元のファイルを復元します。他のプログラムが復元を妨げた場合は、バックアップと対応表を保存したフォルダーが表示されます。

### リンクからカードと世界書を取り込む

世界書画面でリンク取り込みを選び、公開 HTTPS URL を読み込みます。世界書 JSON、GitHub の具体的なファイルページ、世界書入りの JSON／PNG カードに対応します。カードからは世界書だけを取り出します。

キャラクターカード画面にもリンク取り込みがあります。カード JSON またはデータ入り PNG を読み込み、アバター、各欄の本文、別の挨拶を確認して、内蔵世界書も含めるか選べます。任意欄の空白は保持し、PNG のアバターは縮小して保存します。一緒に取り込んだ世界書は書き出し欄で選択されます。最初はカードだけを取り込み、後で同じリンクから世界書を追加しても、編集済みの本文は残ります。

書名、項目、常時有効・無題の件数をプレビューし、原文検索や保存名の変更後に取り込みます。重複は編集済みの既存版を開き、同じ出典の更新は別の本として保存します。通知から取り消せますが、その後の編集を消すことはできません。

カードも重複を省略し、更新は別版として保存します。取り消しでは今回追加したカード、アバター、世界書を戻せます。その後の編集や他の参照がある場合は稿を保護して取り消しを止めます。

Discord は添付 JSON／PNG のダウンロードリンクを使います。投稿やチャンネルからの取得にはサーバーの許可と別の Bot 連携が必要です。期限切れなら原投稿からリンクを取り直してください。添付取り込みに個人の Discord Token や AI は使いません。

上限は 12 MB で、中止とタイムアウトに対応します。デスクトップ版は公開 HTTPS ファイルを取得し、GitHub と Discord CDN の添付にはシステムプロキシを優先して使います。ウェブ版は出典の CORS 設定に依存します。失敗時はデスクトップ版か、保存したファイルの取り込みを使えます。保存する出典 URL からクエリを除き、一時的なダウンロード署名はライブラリへ残しません。

## 保存・バックアップ・更新

資料はブラウザーまたはデスクトップ版の `IndexedDB` に保存し、GitHub へ自動コミットしません。ブラウザープロファイル、ポート、`localhost` と `127.0.0.1`、ファイルページと Electron は別ライブラリになり得ます。いつも同じ入口を使い、移行には全体バックアップを利用します。 旧 localStorage の資料を初回起動時に移行し、元のコピーも保持します。

IndexedDB v6 は作品を個別のレコードに保存します。カードの項目を編集すると、そのカードと更新情報を書き込みます。画像データと会話本文は別レコードに保存され、画像名やブックマークの変更時には関連するメタデータだけが更新されます。ライブラリ全体のインポートや置き換えでは全データを検証します。

v5 のライブラリを初めて開くとデータベースが v6 に更新されます。v0.2.0 も引き続き使う場合は、更新前にアプリを終了し、v5 のユーザープロファイル全体のコピーを別に保管してください。

全体バックアップ JSON（`backupVersion: 2`）は、作品、未収録のカード・ワールドブックの下書き、削除済み作品を含む版履歴、作品別の保存設定、モデルの応答原文を IndexedDB の単一トランザクションで取得します。置き換えはこれらを一緒に復元します。統合では同じ記録を重複させず、同じ ID で内容が異なる下書き・応答は別に残し、履歴を収めるよう保存上限を広げます。統合後の応答が24件を超える場合はすべて保持し、以降の保存枠をその件数に広げます。旧形式からの復元では端末の作業記録を保持します。モデルの接続設定、API キー、端末の保存先は端末内に保持します。バックアップには私的な原稿と応答原文が含まれます。

バックアップ画面の「作品を個別に復元」では、ファイルからカードやワールドブックを検索し、端末の原稿と比較できます。一緒に復元する画像、関連するワールドブック、スナップショットを選択してください。既定では、独立したコピーを作成します。

各作品の「バージョン履歴」から「この作品のスナップショットを管理」を開くと、件数と内容の推定容量が表示されます。保存数を設定する場合も履歴を消去する場合も、対象の日付を確認してから確定できます。空欄は無制限です。指定した上限は今後の手動・自動スナップショットにも適用されます。容量は内容の UTF-8 JSON バイト数から推定します。 全体バックアップの「ライブラリ全体のスナップショット容量」では合計を確認でき、削除済み作品の履歴もプレビューして整理できます。

`npm run test:ui` の保存テストは、64 KiB と 16 MiB の合成画像・会話データで同一項目を5回保存し、入力処理と保存時間の中央値を表示します。1作品に8 KiBずつ5回追記したときのスナップショット容量も記録します。結果は端末やデータによって変わります。

単独で書き出したチャット閲覧用ファイルを読み込むと、メッセージ、ブックマーク、元の SillyTavern ヘッダーが復元されます。キャラクターを削除する前に参照箇所を確認し、リンクの解除、別のキャラクターへの置き換え、台詞の話者名の保持を選べます。キャラクターカード、ワールドブック、画像素材、チャット、グループ、正規表現、クイック返信セットは、削除直後の通知から削除を取り消せます。

バックアップの統合前に競合する項目を展開し、異なる段落を並べて確認できます。項目ごとに「現在の内容を保持」（初期値）、「バックアップを採用」、「両方を別々に保存」を選びます。同じ作品の複数項目を別々に保存すると、新しい ID の作品が一つ追加されます。分岐したチャットにはそれぞれのブックマークが残ります。設定や HTML メモの別版はバックアップ画面で開けます。プレビューをキャンセルすると現在のライブラリを保持します。

Windows デスクトップ版は互換性のため `%APPDATA%\nijan` にユーザーデータと `folders.json` を保存します。表示上の名前は Quilvori／叙翎集です。

バックアップにはカード、本、画像などの作品が含まれます。自分で管理できる場所へ保存し、端末・ブラウザー・ポートの変更や更新前に書き出してください。Git の無視設定だけに頼らず、コミット前にステージ済みファイルを確認してください。

未処理のコード変更がなければ、次で更新できます。

```bash
git pull --ff-only
npm ci
```

その後アプリを再起動するかページを更新します。ウェブ版のみなら `npm ci` は不要です。ローカルコードの変更は更新前に保存・整理します。

## よくある問題

**人物一覧が空です。** 元と同じブラウザー、ポート、デスクトップ入口か確認します。ウェブ版ではファイルを取り込み、デスクトップ版では設定済みフォルダーを読めます。選んだフォルダーが別ブラウザーの庫へ共有されるわけではありません。

**PNG が取り込めません。** 普通の画像にはカードデータがありません。有効なカード PNG、または酒館から出した JSON を使います。

**接続・生成が失敗します。** URL、キー、モデル、方式を確認します。Chat Completions のみなら明示的に選びます。ブラウザーのクロスオリジン通信はサービス側の設定に依存します。切断や容量超過では対象を減らして分割します。

**推論強度が拒否されます。** モデルの既定値または対応する段階へ戻します。

**保存容量が足りません。** 先にバックアップし、大きな画像を減らします。復元できることを確認せずブラウザーデータを消さないでください。

**酒館へ自動で反映されません。** 工房の庫と酒館のファイルは別です。書き出して対応する画面から取り込みます。

## 検証とソース

```bash
npm run validate
```

`npm run validate` は JavaScript の構文、カード・ワールドブック・プロンプトプリセット変換の型、生成済みコードとソースの一致を確認し、動作テストを実行します。変換処理のソースを変更したら `npm run build:formats` を実行してください。CI は Ubuntu と Windows の Node.js 22・24 で検証します。

テストはサンプルと模擬 API を使い、有料モデルを呼びません。入出力、重複防止、原文移動、メタデータ整理、編集範囲、空欄、古いプレビュー、反映・取り消し、引用根拠、通信方式、推論設定、多言語を検証します。

`js/` は UI・ライブラリ・AI 処理、`electron/` はファイル連携、`css/` は外観、`test/` は自動検証です。ウェブ版は通常のスクリプトを使い、バンドラーは不要です。
